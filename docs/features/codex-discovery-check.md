# Codex discovery acceptance check

Run `just verify-codex-discovery <native-codex-path>` to check the selected installed Codex CLI's local project-root marker behavior. The command runs `debug prompt-input` from a synthetic nested Git repository twice: once with default settings and once with the literal `project_root_markers=["stack.lock.json"]` override. The synthetic parent contains a marker and an `AGENTS.md` sentinel. Each run gets an empty fixture-local `CODEX_HOME`, isolated home and temp directories, a minimal process environment, and a bounded timeout.

The check parses prompt input in memory and prints a minimal JSON summary: `status`, `pass`, a validated `cliVersion`, the two sentinel booleans under `proof`, and one fixed `diagnostic` category. Categories are `none`, `missing-cli`, `unsupported-shim`, `timeout`, `output-too-large`, `launch-error`, `version-check-failed`, `invalid-version`, and `marker-mismatch`. Process output, argument values, paths, and raw errors are not included. It does not print or save assembled prompt text. A missing CLI, unsupported shell shim, invalid JSON, timeout, or unexpected sentinel result cannot pass. Temporary files are removed from only the owned absolute fixture directory; cleanup trouble is a path-free warning and does not change the recorded proof.

This check verifies local Codex marker semantics. It does not test T3 launch arguments, hook invocation or trust, skill catalog/body loading, or model inheritance. The named recipe is optional local acceptance and is not a CI requirement because Codex may not be installed.
